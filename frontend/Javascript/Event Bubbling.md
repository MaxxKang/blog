# 이벤트 버블링

이벤트 버블링은 DOM 요소에서 이벤트가 발생했을 때, 해당 요소에서 시작해 최상위 요소인 `Window`까지 거품이 올라가듯 순차적으로 이벤트가 전파되는 현상이다.  

## 이벤트 위임

이벤트 위임은 버블링의 특성을 활용하는 실무적인 코딩 패턴이다.  
여러 개의 하위 요소(자식)에 각각 이벤트 리스너를 달지 않고, 상위 요소(부모)에 단 하나의 이벤트 리스너만 달아서 하위 요소들의 이벤트를 한 번에 제어하는 방식이다.  
다음 예제를 보며 알아보자.
```javascript
// HTML 구조:
// <ul id="itemList">
//   <li class="item">사과 <button class="delete-btn">삭제</button></li>
//   <li class="item">바나나 <button class="delete-btn">삭제</button></li>
// </ul>

// 1. 개별 li나 button이 아닌, 최상위 부모인 ul 요소 하나만 선택해요.
const itemList = document.getElementById('itemList');

// 2. 부모 요소에 단 하나의 이벤트 리스너를 등록해요.
itemList.addEventListener('click', (event) => {
  
  // event.target은 사용자가 정확히 클릭한 픽셀 위치의 요소예요.
  // 클릭된 요소가 삭제 버튼인지, 아니면 리스트의 빈 공간인지 확인해야 해요.
  
  // closest('.delete-btn')은 클릭된 요소 자신부터 시작해서 위로 올라가며
  // '.delete-btn' 클래스를 가진 요소를 찾아요. (버튼 내부의 텍스트나 아이콘을 클릭했을 때를 대비한 안전한 방법이에요)
  const deleteBtn = event.target.closest('.delete-btn');
  
  // 만약 클릭된 요소(또는 그 조상)가 삭제 버튼이 아니라면 이벤트를 무시하고 함수를 종료해요.
  if (!deleteBtn) {
    return;
  }
  
  // 삭제 버튼이 맞다면, 버튼이 속한 전체 아이템(li)을 찾아서 화면에서 지워요.
  const itemToDelete = deleteBtn.closest('.item');
  if (itemToDelete) {
    itemToDelete.remove();
    console.log("아이템이 정상적으로 삭제되었습니다.");
  }
});
```
위 예제의 핵심은 실제 삭제 버튼인 자식요소에는 클릭을 감지하는 `addEventListener`가 아예 없다는 사실이다.  
이벤트 위임 패턴에서는 100개의 리스트 아이템과 삭제 버튼이 있더라도, 리스너는 오직 최상위 부모인 `<ul>` 요소 단 1개에만 존재한다.  
버튼에 리스너가 없는데도 동작할 수 있는 이유가 바로 버블링 때문이다.

## 클릭부터 삭제까지의 실제 흐름

1. 이벤트 발생: 사용자가 `<button>`을 클릭. 하지만 이 버튼에는 클릭을 처리할 리스너 코드가 연결되어 있지 않기 때문에 아무 일도 일어나지 않는다.

2. 버블링 시작: 클릭 이벤트가 DOM 트리를 타고 위로(상위 요소로) 올라가기 시작한다.
  `<button>` -> `<li>` -> `<ul>` 순서로 이벤트가 전파된다.

3. 부모 리스너 감지: 이벤트가 부모인 `<ul>`에 도달하는 순간, `<ul>`에 등록되어 있던 유일한 `addEventListener`가 해당 클릭 이벤트를 감지하고 실행된다.

4. 타겟 추적 및 삭제 로직 실행: 부모(`<ul>`)의 이벤트 리스너 함수 내부에서 `event.target`(클릭 이벤트가 최초로 발생한 진원지)을 확인한다.
   그 진원지가 `<button>`임을 확인한 뒤, 해당 버튼을 감싸고 있는 `<li>`를 찾아내 DOM에서 제거한다.

결국 클릭을 자식 요소에서 했지만, 이벤트를 전달받아 실제 삭제 코드를 실행하는 주체는 부모 요소(`<ul>`)이다.  
자식이 발생시킨 이벤트를 부모가 버블링을 통해 대신 전달받아 처리하기 때문에 부모와의 연결은 필수적이다.

## 부모에게 통제권을 넘기는 이유

- 메모리 절약: 리스트 아이템이 1,000개라면 버튼에 일일이 리스너를 달 경우 브라우저 메모리에 1,000개의 함수 객체가 생성된다.
  부모에게 위임하면 1개의 리스너만으로 1,000개의 버튼 클릭을 모두 제어할 수 있게 된다.

- 동적 DOM 조작 시 안정성: 예제에서 새로운 자식 요소인 `<li>`를 추가한다고 할 때, 개별 버튼에 리스너를 다는 구조라면, 새로운 버튼이 DOM에 추가될 때마다 매번 `addEventListener`를 새롭게 바인딩해 줘야한다.
  반면 부모요소에 위임해 두면, 새로 생성된 자식 버튼을 클릭해도 이벤트가 부모로 버블링되기 때문에 아무런 추가 설정 없이 곧바로 삭제 기능이 정상 동작하게 된다.
